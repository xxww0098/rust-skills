# tauri/security — Capabilities、权限、Scope、CSP 与安全基线

目的：项目出现 `src-tauri/capabilities/*.json`、`app.security`、ACL 报错（`not allowed by ACL` / `Permissions associated with this command`）、自写插件 `permissions/` 或 `persisted-scope` 依赖时加载；给 TA-12 与 TA-14..18 的具体落法与上线审计清单。体积/IPC 通道回 [../tauri.md](../tauri.md)，路径与平台差异回 [../xplat.md](../xplat.md)，`/rust-skills:rust audit security` 的全仓安全面见 [../audit.md](../audit.md)。

## capability 文件与加载（TA-14）

1. 一个 capability = 「哪些窗口/webview × 哪些平台 × 本地还是远程 × 权限列表」。字段：`identifier`（唯一）、`description`、`windows`（窗口 label glob，如 `"editor-*"`）、`webviews`（多 webview 时按 webview label）、`platforms`（`linux`/`macOS`/`windows`/`android`/`iOS`，大小写精确；省略 = 全平台）、`local`（默认 true）、`remote.urls`、`permissions`。
2. 默认自动加载 `capabilities/` 下所有文件；`tauri.conf.json` 的 `app.security.capabilities` 一旦非空就只启用列出的 identifier——新加文件不生效先查这里。
3. 同一窗口命中多个 capability 取并集；任何一处 `deny-*` 或 deny scope 都压过 allow。`windows: ["*"]` 只放 `core:default` 级别的东西，fs/shell/http 必须绑定具名窗口。
4. 引用权限的插件必须同时满足：`Cargo.toml` 依赖 + `.plugin(tauri_plugin_x::init())` + capability 条目 + 前端 `@tauri-apps/plugin-x`。缺依赖 → 构建期「unknown permission」；缺 capability → 运行期 ACL 拒绝。不要用 `*:allow-all` 或加一堆 `:default` 治报错：运行时错误文案已给出缺哪条权限，只加那条（TA-12）。
5. 应用自己的 command 默认对所有窗口开放；要按窗口限制，`build.rs` 用 `tauri_build::AppManifest::new().commands(&["write_note"])` 生成 `allow-write-note`/`deny-write-note` 再写进 capability。`removeUnusedCommands`（TA-02）只裁 ACL 未授权的命令，动态 ACL 不算。
6. 生成物：`src-tauri/gen/schemas/` 是 `tauri dev/build` 产出的 capability JSON schema，gitignore（模板默认已忽略）；插件仓的 `permissions/autogenerated/` 与 `permissions/schemas/schema.json` 随 crate 发布，**必须入库**。

## 权限标识与 scope（TA-15）

| 形态 | 含义 |
|---|---|
| `core:default` | core 各模块 default 集合；`core:window:default` 只含只读查询，`minimize`/`close`/`start-dragging`/`set-size` 需逐条 `core:window:allow-*` |
| `<plugin>:default` | 插件作者定义的默认集，多数插件等于「全部命令 + 无 scope」，不是「最小」 |
| `<plugin>:allow-<cmd>` / `deny-<cmd>` | 单命令；deny 优先 |
| `fs:read-files` / `fs:write-files` 与 `fs:scope-appdata-recursive` 等 `fs:scope-*` | 前者只开命令**不带 scope**，后者只给 scope 不开命令；单独写任一个都什么都读不到 |
| `fs:allow-appdata-read-recursive` 等 `fs:allow-<dir>-<op>[-recursive]` | 命令集合 + scope 一起给；`$APP*` 家族内最省事的最小集 |
| 对象形式 `{ "identifier", "allow": [ … ], "deny": [ … ] }` | 单条命令 + 自定 scope；fs 用 `path`，http 用 `url`，shell 用 `name/cmd/args/sidecar`，opener 用 `url`/`path` |

1. 路径变量：`$APPCONFIG` `$APPDATA` `$APPLOCALDATA` `$APPCACHE` `$APPLOG` `$RESOURCE` `$TEMP` `$HOME` `$DOCUMENT` `$DOWNLOAD` `$DESKTOP` `$EXE` 等；禁手写绝对路径（XP-04）。glob：`$APPDATA/*` 只到直接子项，`$APPDATA/**` 递归，`read_dir($APPDATA)` 还要单独列出目录本身 `$APPDATA`。Unix 默认 `*` 不匹配点文件，需要时 `plugins.fs.requireLiteralLeadingDot: false`。
2. 写权限的 scope 不要碰 `$RESOURCE`/`$EXE`（自毁安装），读权限不要给 `$HOME/**`（等于全盘）；敏感子目录用 `deny` 挖洞。
3. `http` 插件的 fetch 绕过 CORS，scope 的 `url` 是唯一的出站白名单，写精确域名；`shell:allow-execute` 的 `args: true` 等于任意参数，改为 `args: [{ "validator": "^[a-z0-9-]+$" }]` 列表；`shell:allow-open` 是旧路，外链用 `opener:allow-open-url` 带 `url` scope。`opener:default` 允许任意 `http(s)`/`mailto`/`tel`，前端注入即可跳钓鱼页，需要收紧时改对象形式。
4. barcode-scanner/geolocation 的 `allow-check-permissions` + `allow-request-permissions` 必须成对给，缺一则 `checkPermissions()`/`requestPermissions()` 被 ACL 拒；biometric（authenticate/status）与 nfc（is-available/scan/write）没有这两条命令，写进 capability 会构建期报 unknown permission。Tauri ACL 与 `AndroidManifest.xml`/`Info.plist` 的系统权限是两层，缺任一层都失败。

## 按窗口、平台、远程内容拆分（TA-16、TA-23）

1. 一窗一文件，文件名 = 窗口用途；运行时用 `WebviewWindowBuilder` 创建的窗口 label 要落在某个 capability 的 `windows` glob 里，否则它调不到任何插件/core 命令——`listen`、fs、dialog 全拒；应用自己的 command 除非用 `AppManifest` 声明过权限否则仍能调，「自定义命令正常、插件命令全拒」正是漏配的典型症状。前端开新窗还需 `core:webview:allow-create-webview-window`。桌面/移动各一套（上面两个文件）；桌面再按 OS 拆只在托盘、自启这类平台专属插件时才值得（XP-09）。
2. 远程内容（第三方站点、内嵌文档、OAuth 页）默认零 IPC。要给就单独一个 capability：`"local": false` + `"remote": { "urls": ["https://docs.example.com/*"] }` + 只放 `core:event:allow-listen` 这类不碰本机的权限；fs/shell/http/opener 永远不进 remote capability。事件载荷本身也要按「对方能看到」设计。
3. 导航守卫是 ACL、CSP 之外的第三道闸门：`remote.urls` 只管「远程页面能调什么」，拦不住「本地页面被诱导跳到远程」——跳走后 ACL 按 `Origin::Remote` 解析（本地 capability 不再命中），但用户还在你的窗口里，钓鱼面照旧，且 `urls` 写宽一点就直接把权限送出去。建窗时用 `WebviewWindowBuilder::on_navigation(|url: &Url| -> bool)`，返回 false 取消导航，把窗口钉死在本地资源上，外链一律交 `opener:allow-open-url`：

```rust
.on_navigation(|url| {
    url.scheme() == "tauri"                               // macOS/Linux/iOS：tauri://localhost
        || url.host_str() == Some("tauri.localhost")      // Windows/Android：http(s)://tauri.localhost
        || (cfg!(dev) && url.host_str() == Some("localhost")) // devUrl
})
```

`tauri::Builder` 没有 `on_navigation`，`tauri.conf.json` 里 `app.windows` 声明的窗口只能靠插件钩子：`tauri::plugin::Builder::new("nav-guard").on_navigation(|webview, url| …)` 对所有 webview 生效，与 builder 守卫任一返回 false 即取消。`on_page_load` 在导航已发生后才触发，只能做注入，不能当鉴权。远程内容窗口必配守卫。

## CSP、headers、isolation（`tauri.conf.json` → `app.security`；TA-17）

```json
"security": {
  "csp": {
    "default-src": "'self'",
    "connect-src": "ipc: http://ipc.localhost https://api.example.com",
    "img-src": "'self' asset: http://asset.localhost data:",
    "style-src": "'self' 'unsafe-inline'"
  },
  "freezePrototype": true,
  "assetProtocol": { "enable": true, "scope": { "allow": ["$APPDATA/media/**"], "deny": [] } },
  "headers": { "Cross-Origin-Opener-Policy": "same-origin", "Cross-Origin-Embedder-Policy": "require-corp" }
}
```

1. 脚手架默认 `"csp": null` = 没有 CSP，上线前必须填。`connect-src` 必须同时含 `ipc:` 与 `http://ipc.localhost`（IPC 在 macOS/Linux/iOS 走 `ipc://localhost`，Windows/Android 走 `http://ipc.localhost`），缺一则对应平台所有 `invoke` 静默失败。`convertFileSrc` / `blob:` / `data:` 媒体要在 `img-src`/`media-src` 显式放行对应 scheme，接上真路由前先补 CSP。
2. 构建时 Tauri 给 `frontendDist` 里的内联 `<script>`/`<style>` 自动注入 nonce/hash，并把 `asset:`/`http://asset.localhost` 补进 CSP；`dangerousDisableAssetCspModification: true`（或指令数组）关掉后这些全要手写。运行时注入的样式属性不在 nonce 覆盖内，CSS-in-JS 方案给 `style-src 'unsafe-inline'` 可接受；`script-src` 永远不放 `'unsafe-inline'`/`'unsafe-eval'`。
3. `devCsp` 只作用于 `tauri dev`，为 null 时沿用 `csp`；HMR 需要 `ws:` 时写进 `devCsp`，不污染生产 `csp`。
4. `assetProtocol.enable` 打开才有 `convertFileSrc`（TA-07）；scope 是 webview 能直接读的文件范围，与 fs scope 独立；dialog 选中的路径会被运行时同时加进 fs 与 asset scope。
5. `headers` 只作用于 Tauri 自身协议的响应（`tauri://localhost` / `http://tauri.localhost`），`devUrl` 的开发服务器需自配（vite `server.headers`）；`Content-Security-Policy` 不走这里。COOP/COEP 两头是 `SharedArrayBuffer`（wasm 线程）的前提。
6. `freezePrototype: true` 冻结 JS 内建原型，挡原型污染；老 polyfill 可能炸，开了就全量回归一遍。
7. `pattern: { "use": "isolation", "options": { "dir": "../dist-isolation" } }`（目录含 `index.html` + 注册 `window.__TAURI_ISOLATION_HOOK__ = payload => payload` 的脚本）：所有 IPC 先过沙箱 iframe 加密再进 Rust，钩子里可做最后一道校验/拒绝。值得开的条件：前端依赖树大且不可审、加载远程内容、或处理高价值数据；代价是每条 IPC 多一跳和一套独立构建，纯本地工具类应用留默认 brownfield。`app.withGlobalTauri: false` 同理：用 npm 包时不需要 `window.__TAURI__`，关掉少一个注入面。

## 自写插件权限

```rust
// build.rs（tauri-plugin-<name> crate）
const COMMANDS: &[&str] = &["ping", "read_config", "write_config"];

fn main() {
    tauri_plugin::Builder::new(COMMANDS).build();
}
```

```toml
# permissions/default.toml
"$schema" = "schemas/schema.json"

[default]
description = "只读命令；写入需显式授予 allow-write"
permissions = ["allow-ping", "allow-read-config"]

[[set]]
identifier = "allow-write"
description = "写配置"
permissions = ["allow-write-config"]
```

1. `build.rs` 按 `COMMANDS` 生成 `permissions/autogenerated/commands/<cmd>.toml`（`allow-<cmd>`/`deny-<cmd>`）与 `reference.md`；手写的只有 `default.toml` 和自定义 `[[permission]]`/`[[set]]`。`default` 集只放无副作用命令，写/删/网络命令单独成 set 让应用按需开。
2. 命令需要 scope 时：`Builder::new(COMMANDS).global_scope_schema(schemars::schema_for!(ScopeEntry))`，命令签名收 `tauri::ipc::CommandScope<ScopeEntry>`（或 `GlobalScope<ScopeEntry>`），在命令体内按 `scope.allows()`/`scope.denies()` 判定——scope 只是数据，**插件代码不检查就等于没配**。
3. 插件的 `Cargo.toml` `links = "tauri-plugin-<name>"` 与 `tauri-plugin` 放 `[build-dependencies]`；应用侧引用为 `<name>:default`（去掉 `tauri-plugin-` 前缀）。

## 命令层：ACL 之后仍要校验（TA-18）

ACL 决定「谁能调哪条命令、带什么 scope」；命令参数本身不经 ACL。收 `PathBuf`/`String` 路径的应用命令要自己防穿越（XP-05、API-08）：

```rust
#[tauri::command]
async fn write_note(app: tauri::AppHandle, rel: String, body: String) -> Result<(), String> {
    use tauri::Manager;
    let root = app.path().app_data_dir().map_err(|e| e.to_string())?;
    let root = dunce::canonicalize(&root).map_err(|e| e.to_string())?;
    let target = root.join(&rel);
    let parent = dunce::canonicalize(target.parent().ok_or("bad path")?).map_err(|e| e.to_string())?;
    if !parent.starts_with(&root) {
        return Err("path escapes app data dir".into());
    }
    tauri::async_runtime::spawn_blocking(move || std::fs::write(target, body))
        .await
        .map_err(|e| e.to_string())?
        .map_err(|e| e.to_string())
}
```

复用 fs 插件运行时 scope 也可以：`use tauri_plugin_fs::FsExt; app.fs_scope().is_allowed(&target)`（dialog 授权过的路径在内）。数字/枚举参数用 newtype/`enum` 在反序列化时卡死非法值（SE-07），前端 bindings 走 tauri-specta（TA-13）顺带消灭裸字符串命令名。错误返回给前端前脱敏，不回传完整系统路径与 source 链（OBS-02）。

## persisted-scope（TA-15）

1. `tauri-plugin-persisted-scope` 把运行时通过 dialog / `fs_scope().allow_*` 动态加入的 fs 与 asset scope 写到应用数据目录的 `.persisted-scope`，重启后恢复。只有 Rust 侧 `.plugin(tauri_plugin_persisted_scope::init())`，没有前端命令，capability 里不用写它；必须注册在 `tauri_plugin_fs::init()` **之后**。
2. 撤销：`app.fs_scope().forbid_file(&p)` / `forbid_directory(&p, true)`，forbid 同样被持久化；没有过期语义——要「授权 30 天」得自己在 store 里记时间戳，启动时到期即 `forbid_*`。给用户一个「清除已授权文件」入口，实现就是删 `.persisted-scope` 后重启。只持久化用户明确选过的路径；代码里 `allow_directory("/", true)` 一次，永久全盘。

## 上线安全清单

| 项 | 检查方法 | 通过标准 |
|---|---|---|
| 权限面 | `rg -n 'allow-\|:default' src-tauri/capabilities/` 对照前端实际调用（specta bindings 或 `rg "invoke\("`） | 每条权限有调用方；无 `*:allow-all`；`windows: ["*"]` 只挂 `core:default` |
| scope | 逐条读对象形式条目 | 写 scope 不含 `$RESOURCE`/`$EXE`/`$HOME/**`；http `url` 精确域名；`shell` 无 `args: true` |
| 远程内容 | `rg -n '"remote"' src-tauri/capabilities/` | 远程 capability `local: false` 且只有 event 类权限 |
| CSP | `jq .app.security.csp src-tauri/tauri.conf.json` | 非 null；`script-src` 无 `unsafe-*`；`connect-src` 含 `ipc: http://ipc.localhost` + 精确 API 域 |
| 外链/进程 | 审 `opener`/`shell` scope 与 Rust 侧 `Command` 调用（XP-07） | URL 白名单；sidecar 走 `sidecar: true`；无拼接 shell 字符串 |
| devtools | `cargo tree -e features -i tauri \| rg devtools`；release 包右键无「检查」 | release 无 `devtools` feature（TA-03） |
| updater | `jq .plugins.updater src-tauri/tauri.conf.json` | `pubkey` 非空、`endpoints` 全 https；私钥只在 CI secret（SH-* 发布流程） |
| 注入面 | `jq '.app.withGlobalTauri, .app.security.freezePrototype'` | 用 npm 包时 `withGlobalTauri: false`；`freezePrototype` 开或记录为何不开 |
| 生成物 | `git check-ignore src-tauri/gen/schemas` | 应用忽略 `gen/schemas`；插件仓 `permissions/autogenerated` 已入库 |

## 验证

1. 构建期：`cargo tauri build` 会校验 capability 里每个 identifier 存在且插件已依赖，过不了就是配置错，不是警告。
2. 运行期：dev 下把每个功能点走一遍，Console 无 `not allowed` 即 ACL 覆盖完整；CSP 缺指令会以 `Refused to …` 报错，或挂 `securitypolicyviolation` 事件收集后一次补齐。
3. 命令层：`tauri = { features = ["test"] }` 后用 `tauri::test::mock_builder()` + `tauri::test::get_ipc_response` 对 `write_note` 喂 `../../etc/passwd` 类输入，断言拒绝（TEST-08）。IPC 与 asset 协议按平台不同，声明支持的每端各跑一次完整冒烟（XP-03）。
